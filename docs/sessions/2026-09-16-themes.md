## Goal

Replace the binary light/dark toggle with a real theming system: multiple
selectable themes, colours **and** fonts, including the requested
**new-brutalist** direction — while keeping the zero-dependency, no-external-
assets promise (DECISIONS §7).

## What was done

- **DECISIONS §16**: themes are flat, named token sets applied via
  `data-theme="<id>"`; registry in `Render.THEMES`; independent of light/dark.
- **Five themes** in `src/styles.css`:
  - `zen` (default light, unchanged look) · `midnight` (the old dark)
  - `paper` (warm light, serif display) · `brutalist` (square, 3px black
    borders, hard offset shadows, orange accent, mono uppercase)
  - `brutalist-dark` (black + acid-yellow, white offset shadows)
- **Structural tokens** so a theme changes shape/type, not just colour:
  `--radius`, `--border-w`, `--check-w`, `--pill`, `--shadow*`, `--glow*`,
  `--on-accent`, `--font`, `--font-display`, `--display-tracking`,
  `--display-transform`. A `[data-theme^="brutalist"]` block handles the few
  non-token overrides (uppercase chrome, hard corners on component radii).
- **Theme picker** (`render.js` `THEMES` + `themePickerHtml`; `app.js`
  `resolveTheme/initTheme/setTheme/syncThemePop/toggleThemePop`): palette button
  in the topbar opens a popover with swatches; persists `ahabit.theme`;
  migrates old `light`/`dark`; Escape/outside-click close it.
- **`<meta name="theme-color">`** now follows the active theme (JS-updated);
  removed the static media metas from the PWA head.
- **Version** → 0.7.0 (About + `package.json`).

## Key decisions & changes

- No separate light/dark axis — 5 named themes is simpler to reason about and
  matches the ask (“more than one option”). Adding a theme = one registry entry
  + one CSS block (DECISIONS §16).
- Contrast-audited every theme in Node (WCAG formula) — caught that white on
  brutalist orange was only 3.57:1, so `--on-accent` is near-black there
  (5.54:1). Zen/midnight/paper all pass.
- `--grad` may be a flat colour (brutalist uses solid orange/yellow); the code
  already treated it as a `background` value, so solid works.

## Context dump

- Adding a theme: add an entry to `Render.THEMES`
  (`{id,name,emoji,scheme,color,colors}`) **and** a `[data-theme="<id>"] {…}`
  token block in `src/styles.css`. Keep `color` = that theme's `--bg` (it feeds
  `<meta name="theme-color">`).
- Prefer the shared structural tokens in component CSS; avoid hardcoded px for
  anything a theme might want to change. `color-scheme` must be set for dark
  families (`[data-theme="midnight"], [data-theme="brutalist-dark"]`).
- `--on-accent` is the ink colour on accent/gradient surfaces (buttons, active
  tab, check, logo, fab) — set it when the accent is light (yellow → black).
- Theme state is UI-only: `localStorage['ahabit.theme']`, like
  `ahabit.welcome.v1`; never in `ahabit.db.v1` (cf. DECISIONS §14).
- Version lives in `app.js` About + `package.json`; both bumped to 0.7.0.
