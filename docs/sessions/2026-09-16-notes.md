## Goal

Add per-check-in notes without breaking the additive-schema discipline from
DECISIONS §9: "Read 20 pages → *finished chapter 3*". Notes should round-trip
through export/import and be editable from Today and the day modal.

## What was done

- **DECISIONS §12** (logged before building, per workflow): notes live in a new
  top-level `notes: { habitId: { 'YYYY-MM-DD': text } }` map — same date-key
  convention as completions, **independent of check-ins**. Toggling or "Clear
  day" never deletes notes; merge fills gaps only.
- **Store** (`src/js/store.js`): `getNote` / `setNote` (trim, 240-char cap,
  invalid keys rejected); `emptyDb`/`load` default + migrate `notes` for
  pre-notes backups; `deleteHabit` cleans up notes; `importJSON` sanitizes
  notes (known habit ids + valid keys only); `mergeWith` gap-fills;
  `loadSample` seeds a few notes.
- **Render** (`src/js/render.js`): Today rows show an inline note field when the
  habit is done **or** already has a note; the day modal shows a note field for
  every habit (backfill-friendly).
- **App** (`src/js/app.js`): one new **delegated `input` listener**
  (`data-action="note"`) live-saves notes — no per-field listeners, no
  re-render on keystroke.
- **CSS**: `.note-field` styling (stays on-theme, responsive).
- **Tests** (`scripts/smoke.js`): trim/cap/clear/edge cases, import
  sanitization, merge/replace round-trips, sample-data note, and that rendered
  Today HTML contains note inputs. `querySelector` stub now memoizes so tests
  can inspect rendered `innerHTML`.

## Key decisions & changes

- Schema stays `{version:1}` and additive (no bump, per §9's guidance).
- Notes are plain text and deliberately excluded from streaks/analytics.
- Clearing a day's check-ins does **not** clear its notes (never destroy user
  text) — documented in §12.
